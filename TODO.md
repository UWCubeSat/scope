# SCOPE: known gaps

Written 2026-10-09 at the merge of the `star-centroid` branch, and updated the same day after a follow-up pass that added the attitude input, the `--roi-size` option, clean error handling, and tests for the command-line and provider code. Updated 2026-10-21 for the `optimizer` branch, which adds the Levenberg-Marquardt fit, the synthetic data generator `scope-synth` and `synthetic-e2e.sh`. The pipeline now produces a calibration, and recovers the truth from synthetic star images; it has not been run on real ones.

## Needed before the pipeline does real work

- **The output is a printout and two optional files.** `PrimaryScopePipelineExecutor::OutputResults` (`src/scope/command-line/execution/executors.cpp`) prints the fitted parameters with their uncertainties, the residual RMS, the alignment correction and the fitted parameters as flags. `--output-attitudes` writes the refined attitudes and `--output-residuals` a CSV of every observation. The handoff format to FOUND is undecided, because neither FOUND's nor LOST's `Camera` accepts distortion parameters yet.
- **Nothing produces the attitudes file.** `--attitudes` reads attitudes that are already in SCOPE's camera frame (see below). Converting a plate solver's or a star tracker's output into that frame is left to whatever writes the file. For LOST the conversion is `LostAttitudeToScopeFrame` (`src/scope/projection/projection.hpp`); for astrometry.net it has not been written.
- **The uncertainties are optimistic on real centroids.** They are the covariance of the fit and match the actual scatter when centroid errors are Gaussian, but on rendered images they are 10–30% too small (`reference/OPTIMIZER_DESIGN.md` §4). Check a calibration by fitting two disjoint sets of images, as the plan says.

## Known gaps in the optimization stage

- **No automatic second pass.** Re-centroiding with the fitted parameters and a smaller window (STATUS §5.2) has to be done by hand: pass the printed `as-prior:` flags and the `--output-attitudes` file back in with a smaller `--roi-size`.
- **Dense normal equations.** The state is 10 + 3m, and the solve is O(m³) per step. That suits the paper's 15 images, and validating 300 synthetic images in one run (900 states, 58,000 observations) took 50 s in the default unoptimized build on 2026-10-21. Far more than that would want the per-image block structure exploited (a Schur complement).
- **No soft priors.** Each parameter is either estimated freely or fixed (`--fixed-parameters`); STATUS §5.3's prior constraints are not implemented, and neither is weighting by star brightness (§5.6).
- **The alignment correction has no uncertainty.** `CalibrationResult::alignmentCorrection` is the Markley mean of the per-image corrections; the spread of those corrections is not reported.

## Behaviour to be aware of

- **The first argument is skipped.** `main` treats the first argument as a command name and ignores it unless it is `--help` or `-h`, so `./scope --dark-frames ...` silently drops `--dark-frames`. Put any word first: `./scope run --dark-frames ...`.
- **CLI flags.** `--dark-frames` and `--star-images` (comma- or space-separated paths), `--attitudes`, `--catalog-path`, `--centroid-threshold`, `--magnitude-threshold`, `--roi-size`, the ten prior camera parameters, and for the fit `--fixed-parameters`, `--attitude-correction`, `--outlier-threshold`, `--max-iterations`, `--output-attitudes` and `--output-residuals`. `./scope --help` lists them.
- **The principal point is held fixed by default,** at whatever `--principal-point-x` and `--principal-point-y` say, as the paper recommends. With the 6 mm lens it is probably estimable (`reference/LENS.md` §6); `--fixed-parameters none` frees it.
- **`scope-synth` takes no command word.** Unlike `scope`, its flags start at the first argument.
- **Attitudes file.** `--attitudes` is required when there are star images. One line per star image, in the same order: a quaternion `w x y z` that rotates inertial (J2000) directions into SCOPE's camera frame, whose boresight is +z. `#` starts a comment. The loader is `LoadAttitudes` (`src/scope/attitude/`); to take attitudes from somewhere else, change `ProvideAttitudes` in `src/scope/providers/stage-providers.hpp`.
- **A wrong attitude does not fail loudly.** The stage takes the brightest pixel in each window, so with the default 31 px window a wrong attitude still finds plenty of unrelated stars. To check an attitude conversion, run with a small window such as `--roi-size 3`. On synthetic images rendered from the catalog, correct attitudes then found every predicted star and shuffled ones found under 4%. Stage 2 logs how far it moved each image's windows (the median offset of the stars alone in their windows): an offset near half the window means the prior is at the edge of what the window reaches, and stars beyond it are replaced by whatever else is in their windows. On synthetic images with misalignments drawn at 1500″ per axis (about 13 px), the fit then converged to residuals of 7–9 px on a quarter of the data sets; widen `--roi-size` for a first pass when the mounting is poorly known.
- **The prior needs the lens's distortion.** The ten prior camera parameters default to zero, and a zero focal length is now an error when there are star images. The lens is an Edmund Optics #35-142 (6 mm, f/4) with −6.8% barrel distortion at the edge of its image circle. On the candidate 3.45 µm, 2064 × 1544 sensor, a prior with the right focal length (1739 px) but `k1 = k2 = 0` predicts stars 53 px off at the left and right edges and 92 px off in the corners, so the default 31 px window only finds stars in the middle 44% of the frame. Values read from the datasheet's distortion curve are `--k1 -0.157 --k2 0.082`; they describe the nominal design, not the unit in hand, so widen `--roi-size` on the first pass.
- **The catalog file is required.** `--catalog-path` defaults to `./bright-star-catalog.tsv`, fetched by `download-bsc.sh` (needs `curl` or `wget`; it returned 9,096 stars on 2026-10-09). A missing catalog, an unreadable image or a bad attitudes file now ends the run with an error message and exit code 1.
- **Frames must be 8-bit when they reach SCOPE.** Images are loaded with `stbi_load`, which keeps only the top byte of a 16-bit PNG. A 12-bit frame stored in the low bits of a 16-bit file therefore arrives with every pixel between 0 and 15, below any useful threshold. The camera (XIMEA MC031MG-SY-FL) should be captured at 12 bits, because its 8-bit mode at zero gain puts `--centroid-threshold 40` at about 440 electrons, which a 2 s exposure reaches only for stars of magnitude 2.4 or brighter; so until SCOPE reads 16-bit images, frames need a deliberate scale-and-clip conversion to 8 bits first. TIFF is not readable at all.
- **`FLOAT_MODE` does not make SCOPE single precision.** The option defines `SCOPE_FLOAT_MODE`, but `decimal` comes from FOUND and switches on `FOUND_FLOAT_MODE`, which only FOUND's own library is compiled with. In a `-DFLOAT_MODE=ON` build SCOPE's code is still `double` while FOUND's is `float`, so that build passing says nothing about SCOPE in single precision.

## Design issues still open in the star-centroid stage

- **Images are 8-bit.** `Image` is `unsigned char` (inherited from FOUND), so the dark frame, the dark subtraction and `--centroid-threshold` are all 8-bit. Moving to 16-bit pixels needs a SCOPE-owned image type and loader; it was deferred on 2026-10-09 until real frames show what format and bit depth the camera saves.
- **Mask radius and collision distance are constants.** Both are 3 px (`src/scope/star-centroid/star-centroid.cpp`). Only the search window became an option.
- **Which image centre the principal point defaults to.** SCOPE treats an integer coordinate as a pixel centre, which matches FOUND's edge points (decided 2026-10-09, recorded in `src/scope/star-centroid/coi.hpp`); LOST's centroids are 0.5 px larger. Under that convention the centre of a W-pixel-wide image is (W − 1) / 2, but FOUND's ideal camera uses W / 2. This matters once the optimizer fixes the principal point to the image centre.
