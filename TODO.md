# SCOPE: known gaps

Written 2026-10-09 at the merge of the `star-centroid` branch, and updated the same day after a follow-up pass that added the attitude input, the `--roi-size` option, clean error handling, and tests for the command-line and provider code. With those changes the build, all 89 tests, lint, coverage (100% of lines) and valgrind pass, and the program runs the dark-frame and star-centroid stages from the command line. It does not yet produce a calibration.

## Needed before the pipeline does real work

- **Optimization is a stub.** `LMAOptimizationAlgorithm` (`src/scope/optimization/`) returns an empty, unconverged `CalibrationResult`. The Levenberg-Marquardt fit is the bulk of the remaining work.
- **The output is a printout only.** `PrimaryScopePipelineExecutor::OutputResults` (`src/scope/command-line/execution/executors.cpp`) prints the `CalibrationResult` to standard output: whether the fit converged, the ten parameters, and the residual RMS. With the stub optimizer that is all zeros and `converged: no`, so the only real result of a run is still one log line per star image giving how many centroids were kept. Nothing is written to a file, and the per-image attitudes and per-observation residuals the result carries are not printed. The handoff format is also undecided, because neither FOUND's nor LOST's `Camera` accepts distortion parameters yet.
- **Nothing produces the attitudes file.** `--attitudes` reads attitudes that are already in SCOPE's camera frame (see below). Converting a plate solver's or a star tracker's output into that frame is left to whatever writes the file. For LOST the conversion is `LostAttitudeToScopeFrame` (`src/scope/projection/projection.hpp`); for astrometry.net it has not been written.

## Behaviour to be aware of

- **The first argument is skipped.** `main` treats the first argument as a command name and ignores it unless it is `--help` or `-h`, so `./scope --dark-frames ...` silently drops `--dark-frames`. Put any word first: `./scope run --dark-frames ...`.
- **CLI flags.** `--dark-frames` and `--star-images` (comma- or space-separated paths), `--attitudes`, `--catalog-path`, `--centroid-threshold`, `--magnitude-threshold`, `--roi-size`, plus the ten prior camera parameters. `./scope --help` lists them.
- **Attitudes file.** `--attitudes` is required when there are star images. One line per star image, in the same order: a quaternion `w x y z` that rotates inertial (J2000) directions into SCOPE's camera frame, whose boresight is +z. `#` starts a comment. The loader is `LoadAttitudes` (`src/scope/attitude/`); to take attitudes from somewhere else, change `ProvideAttitudes` in `src/scope/providers/stage-providers.hpp`.
- **A wrong attitude does not fail loudly.** The stage takes the brightest pixel in each window, so with the default 31 px window a wrong attitude still finds plenty of unrelated stars. To check an attitude conversion, run with a small window such as `--roi-size 3`. On synthetic images rendered from the catalog, correct attitudes then found every predicted star and shuffled ones found under 4%.
- **The catalog file is required.** `--catalog-path` defaults to `./bright-star-catalog.tsv`, fetched by `download-bsc.sh` (needs `curl` or `wget`; it returned 9,096 stars on 2026-10-09). A missing catalog, an unreadable image or a bad attitudes file now ends the run with an error message and exit code 1.
- **Frames must be 8-bit when they reach SCOPE.** Images are loaded with `stbi_load`, which keeps only the top byte of a 16-bit PNG. A 12-bit frame stored in the low bits of a 16-bit file therefore arrives with every pixel between 0 and 15, below any useful threshold. TIFF is not readable at all.
- **`FLOAT_MODE` does not make SCOPE single precision.** The option defines `SCOPE_FLOAT_MODE`, but `decimal` comes from FOUND and switches on `FOUND_FLOAT_MODE`, which only FOUND's own library is compiled with. In a `-DFLOAT_MODE=ON` build SCOPE's code is still `double` while FOUND's is `float`, so that build passing says nothing about SCOPE in single precision.

## Design issues still open in the star-centroid stage

- **Images are 8-bit.** `Image` is `unsigned char` (inherited from FOUND), so the dark frame, the dark subtraction and `--centroid-threshold` are all 8-bit. Moving to 16-bit pixels needs a SCOPE-owned image type and loader; it was deferred on 2026-10-09 until real frames show what format and bit depth the camera saves.
- **Mask radius and collision distance are constants.** Both are 3 px (`src/scope/star-centroid/star-centroid.cpp`). Only the search window became an option.
- **Which image centre the principal point defaults to.** SCOPE treats an integer coordinate as a pixel centre, which matches FOUND's edge points (decided 2026-10-09, recorded in `src/scope/star-centroid/coi.hpp`); LOST's centroids are 0.5 px larger. Under that convention the centre of a W-pixel-wide image is (W − 1) / 2, but FOUND's ideal camera uses W / 2. This matters once the optimizer fixes the principal point to the image centre.
